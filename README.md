# Сетап

Кликер про сборку компьютерного места. Клик = работа = деньги, деньги = железо,
всё купленное железо видно на единственной сцене. Железо греется: прогретая система
работает быстрее, перегретая — троттлит, а блок питания ограничивает, что вообще
можно поставить.

Дизайн-документ и единственный источник правды по механикам — [`CLAUDE.md`](CLAUDE.md).
Здесь описано только то, как это запустить и проверить.

**Состояние: фазы 1–4 из §11 сделаны.**

| Фаза | Что в ней | Готово |
|---|---|---|
| 1. Ядро | 14 категорий по 8 уровней, ватты, тепло, пыль, комбо, магазин, сохранение, адаптив, i18n | да |
| 2. Визуал | освещение, блум, зерно, температура сцены, доставка покупки, день и ночь, частицы | да |
| 2. Звук | подсистема на Web Audio | да, но **без файлов** — см. `assets/sfx/README.md` |
| 3. Долгая игра | заказы, переезд и репутация, оффлайн-доход, кот, достижения | да |
| 4. Платформа | Yandex SDK, облачный сейв, rewarded и межстраничная, сборка архива | да |
| 4. Playgama | адаптер написан | адрес SDK не проверен, см. «Известные расхождения» |

## Как запустить локально

Игра — чистые ES-модули без сборки, поэтому её нужно отдать по http.
Двойной клик по `index.html` не сработает: браузеры блокируют
`import` по протоколу `file://` политикой CORS (проверено, см. «Известные
расхождения»). Любой статический сервер подойдёт:

```bash
python3 -m http.server 8000
# затем открыть http://localhost:8000/
```

Ничего устанавливать не нужно: ни npm, ни сборщиков, ни зависимостей.
`package.json` в корне содержит только `"type": "module"` — он нужен
исключительно для того, чтобы `node` запускал `tools/sim.js` как ES-модули.

## Как поиграть: GitHub Pages

Публикация автоматическая, через GitHub Actions — [`.github/workflows/pages.yml`](.github/workflows/pages.yml).
Любой пуш в ветку игры собирает и выкладывает её заново.

Режим Pages **«GitHub Actions» включился сам** — воркфлоу вызывает
`configure-pages` с `enablement: true`, руками в настройках ничего трогать
не нужно. Если когда-нибудь понадобится проверить: Settings → Pages → Source.

Игра живёт по адресу:

```
https://fleuki.github.io/ClickerPC-GAME/
```

Что делает воркфлоу перед публикацией:

1. проверяет, что все модули разбираются (`node --check`) — сломанная игра не поедет;
2. гоняет симулятор баланса на 40 минут и печатает результат в лог;
3. собирает `_site` из `index.html`, `src/`, `.nojekyll` и прототипа фазы 0
   (он остаётся доступен по `/setup-clicker-prototype.html`);
4. деплоит артефакт на Pages.

Запустить публикацию вручную, ничего не коммитя: вкладка **Actions** → workflow
**Pages** → **Run workflow**.

Игра лежит по относительным путям и корректно работает из подпапки
`/ClickerPC-GAME/`. Проверено на живой сборке: файлы, которые отдаёт Pages,
байт в байт совпадают с репозиторием, игра запускается без единой ошибки
в консоли, клики и покупки работают. Всё, что не нужно игроку — `CLAUDE.md`,
`docs/`, `tools/`, `package.json` — в артефакт не попадает и отдаёт 404.

Проверять правки удобно прямо с телефона: открыть эту ссылку, добавить на
домашний экран и убедиться, что страница не скроллится при свайпе по сцене,
магазин прокручивается, а safe-zone видна целиком.

## Сборка архива для площадки

```bash
node tools/build.js                 # dist/setup.zip
node tools/build.js --name=setup-v2
```

Скрипт ничего не компилирует — сборщика у игры нет и не будет. Он
раскладывает `index.html`, `src/` и `assets/` в `dist/`, пакует их в zip
(своим минимальным упаковщиком: тянуть зависимость ради архива запрещает §2)
и проводит самопроверку требований площадки: нет ли тегов `<audio>`
и `<video>`, заблокирован ли скролл, не захардкожен ли язык. Если что-то
не так, скрипт возвращает ненулевой код — тот же шаг стоит в CI, так что
до публикации сломанная сборка не доедет.

Сейчас архив весит около 74 КБ, распакованный — 200 КБ при бюджете 300 КБ.

## Площадки

Игра сама определяет, где запущена, по адресу страницы. На локальном
сервере и на GitHub Pages включается заглушка: **никаких внешних запросов
игра не делает**, SDK площадки не грузится вовсе. Принудительно выбрать
площадку можно через `PLATFORM.target` в `src/config.js`
(`'auto'`, `'yandex'`, `'playgama'`, `'none'`).

Что делает платформенный слой (`src/platform/sdk.js`):

- **язык** — из SDK, до первого рендера интерфейса;
- **`LoadingAPI.ready()`** — когда игра стала интерактивной;
- **`GameplayAPI`** — сообщает площадке, идёт ли игра, по `visibilitychange`;
- **облачный сейв** — пишется и в облако, и локально; при загрузке берётся
  тот, что новее по `savedAt`. Облако отвалилось — играем на локальном;
- **rewarded** — мгновенная чистка корпуса и удвоение оффлайн-дохода;
- **межстраничная** — только после переезда, не раньше 30 секунд от старта
  сессии и не чаще раза в минуту, как требует §2.

Любая ошибка площадки роняет адаптер в заглушку, а не игру.

## Симулятор баланса

```bash
node tools/sim.js                          # 60 минут при 0, 3 и 5 кликов/сек
node tools/sim.js --minutes=90 --rates=0,3,5,8
```

Симулятор импортирует те же `config.js`, `economy.js` и ту же функцию `step()`,
что и игра, — модель одна на двоих, разъехаться ей негде. Он печатает время
до каждого уровня каждой категории, момент первого затыка по ваттам, момент
первого троттлинга, время до переезда и доход по пятиминутным отрезкам.
Последний прогон лежит в [`docs/balance.md`](docs/balance.md).

**Правило: после любой правки `config.js` — прогон симулятора, и его вывод
прикладывается к изменению.** Числа не подгоняются на глаз.


## Служебная ручка для проверок

В браузерной консоли доступен `window.SETUP`:

```js
SETUP.perf()                       // среднее и максимум времени draw() за 300 кадров
SETUP.state                        // состояние игры
SETUP.economy.totalWatts(SETUP.state.levels)
SETUP.save()                       // принудительный сейв
```

## Известные расхождения с CLAUDE.md

Всё перечисленное — осознанные решения, а не недосмотр.

1. **Числа баланса.** Таблицы §5 давали рост дохода примерно в 6.4 раза за круг
   покупок при росте цен в 4 раза: игра выбивалась в максимум за 66 секунд,
   а порог переезда в 5 млн проходился за минуту. §5 прямо разрешает подгонять
   эти числа симулятором. Изменены только два столбца — `C0` (все ×2) и `m`
   у множительных категорий. `r`, ватты, температурные пороги, пыль, комбо и
   криты — ровно как в документе. Полный список и вывод симулятора:
   [`docs/balance.md`](docs/balance.md).

2. **Ватты на нулевом уровне.** §4.3 отдельно оговаривает, что видеокарта на
   уровне 0 потребляет 0 Вт (встроенная графика). То же правило применено
   к кондиционеру («открытая форточка») и подсветке («нет подсветки»): на нулевом
   уровне этих компонентов в сборке физически нет, платить за них ваттами не за что.
   В `config.js` это явный флаг `zeroWattsAtLevel0`.

3. **Запуск двойным кликом.** §2 требует, чтобы игра открывалась двойным кликом
   по `index.html`, но §2 же требует ES-модули. Одновременно это невозможно:
   браузеры блокируют `import` с `file://` (проверено в Chromium — CORS,
   `origin 'null'`). Промпт фазы 1 разрешает противоречие в пользу локального
   сервера, команда выше. На самой платформе вопрос не стоит: Яндекс.Игры
   отдают игру по https.

4. **Файлы сверх §3.** Структура §3 не предусматривала места для звука,
   кота и достижений, поэтому добавлены `platform/sound.js`, `systems/cat.js`
   и `systems/achievements.js`. Всё остальное лежит ровно там, где сказано.

5. **Звука нет.** Подсистема готова, файлов нет: CC0-наборы Kenney и
   OpenGameArt отдаются только через форму, а синтезировать звук запрещает
   §2 — Playgama помечает такой звук как AI-generated. Что скачать и какой
   флаг переставить — в `assets/sfx/README.md`.

6. **Адрес Playgama Bridge не проверен.** Из окружения, где игра собиралась,
   `bridge.playgama.com` отдаёт 403, поэтому URL в `PLATFORM.playgama.sdk`
   взят по документации и не подтверждён живым запросом. Адрес Yandex SDK,
   наоборот, проверен: отдаёт `var YaGames` со всеми нужными методами.
   Если скрипт Playgama не загрузится, игра останется на заглушке
   и продолжит работать.

7. **Качество картинки подстраивается само.** Полнокадровые эффекты (блум)
   на слабом железе не укладываются в 16 мс, поэтому игра меряет своё время
   отрисовки и снимает эффекты, пока не уложится. Качество только
   понижается: возвращать эффекты обратно — значит получить качели
   и мигание картинки. Вернуть вручную: `SETUP.lighting.setQuality(2)`.

## Требования Яндекс.Игр — самопроверка

- `document.querySelectorAll('audio, video').length === 0` — тегов нет ни одного,
  звука в фазе 1 нет вовсе.
- `sdk.ready()` вызывается в конце `boot()`, когда игра уже интерактивна;
  в фазе 4 внутри него включится `LoadingAPI.ready()`.
- Язык берётся из `platform/sdk.js` до первого рендера интерфейса.
  Хардкода `'ru'` в `src/` нет: `grep -rn "'ru'" src/` ничего не находит.
- Страница не скроллится: `position: fixed` на body плюс `preventDefault`
  на `touchmove` везде, кроме списка магазина.
- Заголовок игры — «Сетап», одинаково во всех полях, без капса.
- Растровых ассетов нет; иконка вкладки — инлайновый SVG в `data:`-адресе.
