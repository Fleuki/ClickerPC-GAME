# Промпт для Claude Code — Фаза 1: ядро игры «Сетап»

*(скопировать целиком в Claude Code в пустом репозитории, рядом положить `CLAUDE.md` и
прототип `setup-clicker-prototype.html`)*

---

Прочитай `CLAUDE.md` в корне репозитория целиком, прежде чем писать код. Это дизайн-документ
проекта, он — источник правды по механикам и числам. Также посмотри
`setup-clicker-prototype.html` — это одностраничный прототип, из которого выросла игра.
Оттуда берётся стиль отрисовки сцены и ощущение механики тепла, но код переписывается с нуля
в модульную структуру, а не переносится копипастой.

## Задача

Собрать **Фазу 1** — играбельное ядро с полноценной экономикой на 14 категорий апгрейдов.
Визуал на этом этапе остаётся на уровне прототипа (плюс новые предметы, которых в прототипе
не было). Освещение, bloom, звук, заказы, престиж, оффлайн, кот — **не в этой фазе**.

## Что должно работать в конце

1. **Структура файлов ровно как в §3 `CLAUDE.md`.** Чистые ES-модули, ноль зависимостей,
   ноль сборки. `index.html` открывается локально и работает.
2. **`config.js` содержит все числа игры** из §4 и §5 `CLAUDE.md` — цены, эффекты, ватты,
   пороги температуры, скорости. В остальных файлах не должно быть ни одного числового
   литерала, влияющего на баланс.
3. **14 категорий апгрейдов** по 8 уровней, три вкладки магазина. Цена и эффект считаются
   по формулам `cost(n) = C0 × r^(n−1)` и `val(n) = V0 × m^n` (или аддитивно, где в таблице
   стоит `+`), а не хранятся таблицей вручную.
4. **Система ватт.** Каждый компонент потребляет мощность, блок питания задаёт лимит.
   Покупка, выводящая за лимит, блокируется, карточка показывает причину текстом вида
   «Не хватает 45 Вт». В HUD видно «занято / лимит».
5. **Система тепла** по §4.2: четыре зоны, троттлинг с гистерезисом (вход при 100°, выход
   при 55°), при троттлинге автоклики останавливаются и пассив режется вдвое. Кнопка
   «Разгон»: 8 сек ×3 к доходу и ×2.5 к нагреву, откат 33 сек.
6. **Пыль** по §4.4: копится, режет охлаждение, чистится мини-действием из шести тапов по
   пыльным зонам корпуса на сцене. Кондиционер замедляет накопление.
7. **Комбо** по §4.5: окно сброса зависит от уровня наушников, множитель до ×2.5, видимый
   индикатор серии рядом с курсором/местом клика.
8. **Сохранение.** Автосейв каждые 15 секунд, на `visibilitychange` и перед выгрузкой
   страницы. Формат — версионированный объект с полем `version` и функцией миграции.
   На этой фазе хранилище — `localStorage` за интерфейсом `platform/sdk.js`, чтобы в фазе 4
   он подменился на облачный сейв Яндекса без правок игровой логики.
9. **Адаптив.** Логическая сцена 1000×700, safe-zone 720×700 по центру гарантированно видна.
   Портрет: сцена сверху, магазин снизу. Ландшафт: сцена слева, магазин справа.
   Учитывается `devicePixelRatio` (ограничить сверху 2). Скролл страницы заблокирован.
10. **Локализация ru/en**, все строки в `i18n.js`. Язык на этой фазе берётся из
    `navigator.language` **через `platform/sdk.js`**, чтобы в фазе 4 источник сменился на SDK.
    Хардкод `'ru'` в коде запрещён.
11. **`tools/sim.js`** — симулятор баланса на node без зависимостей, импортирующий тот же
    `config.js` и `economy.js`, что и игра. Прогоняет 60 игровых минут при темпе 0, 3 и 5
    кликов в секунду и печатает: время до каждого уровня каждой категории, момент первого
    затыка по ваттам, момент первого троттлинга, доход в минуту по пятиминутным отрезкам.

## Порядок работы

Не пиши всё одним куском. Иди шагами, после каждого — рабочая игра и отдельный коммит:

1. Скелет: `index.html`, `main.js`, цикл с фиксированным шагом, пустая сцена, HUD.
2. `config.js` + `economy.js` + `state.js`: экономика без графики, проверяемая через консоль.
3. `tools/sim.js` и первый прогон баланса. **Покажи вывод симулятора и сравни с целями из
   §9 `CLAUDE.md`.** Если тайминги мимо — предложи правки констант, а не подгоняй молча.
4. Магазин, вкладки, ватты, блокировки покупок.
5. Системы: тепло, пыль, комбо.
6. Рендер сцены по слоям, все новые предметы (наушники, кондиционер, накопитель, блок
   питания и прочее видно на сцене или внутри корпуса).
7. Сохранение, адаптив, i18n.

## Запрещено

- Внешние библиотеки, npm, сборщики, CDN, TypeScript-компиляция.
- Теги `<audio>` и `<video>` в любом виде.
- Растровые изображения. Вся графика — код.
- Реализовывать заказы, переезд/престиж, оффлайн-доход, кота, день/ночь, звук, bloom и
  освещение из §7 `CLAUDE.md` — это фазы 2 и 3.
- Больше 4 визуальных состояний на категорию.
- Менять числа из `CLAUDE.md` без вывода симулятора, обосновывающего правку.
- Хранить баланс-константы вне `config.js`.
- Использовать `innerHTML` с игровыми строками (только текстовые узлы) — чтобы локализация
  не сломалась и не появилось лишних уязвимостей.

## Чеклист перед тем, как отчитаться о готовности

Выполни каждый пункт и приложи результат. Не пиши «готово», пока все пункты не отмечены.

- [ ] `document.querySelectorAll('audio, video').length === 0` — вывести результат в консоль.
- [ ] Ни одного числового литерала баланса вне `config.js`: приложить вывод
      `grep -rnE '[^a-zA-Z_][0-9]{2,}' src/ --include=*.js | grep -v config.js` и объяснить
      каждое оставшееся вхождение (координаты рендера — допустимы, эффекты — нет).
- [ ] Игра запускается из чистого `file://` без ошибок в консоли (модули — через локальный
      сервер, приложить команду запуска в `README.md`).
- [ ] Прогон `node tools/sim.js` приложен целиком. Первая покупка < 15 сек, первый затык по
      ваттам 2–4 мин, все 14 категорий куплены хотя бы раз к 8-й минуте.
- [ ] Покупка, превышающая лимит ватт, невозможна ни через UI, ни при быстрых повторных
      тапах. Описать, как это проверено.
- [ ] Троттлинг включается на 100° и выключается только ниже 55°, без дребезга на границе.
- [ ] Перезагрузка страницы сохраняет уровни, баланс, температуру, пыль и комбо-состояние.
- [ ] Сейв со старой версией (изменить `version` вручную) не роняет игру, а мигрирует.
- [ ] На узком экране (360×640) safe-zone видна целиком, магазин прокручивается, страница
      не скроллится при свайпе по сцене.
- [ ] `grep -rn "'ru'" src/` не находит хардкода языка.
- [ ] Кадр укладывается в 16 мс: приложить измеренное среднее время `draw()` за 300 кадров.
- [ ] `README.md` описывает, как запустить локально и как проверить сборку через GitHub Pages.
